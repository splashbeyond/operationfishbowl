# Open Questions

## Product Questions

1. Should the default budget be framed as "distraction time" instead of "screen time"?
2. Should TimeTank show total phone screen time as context, while only judging selected-app time?
3. Should the user choose from presets like 30 min, 1 hr, 2 hr, or enter a custom allowance?
4. Should the first bypass of the day be gentle, with later bypasses becoming more serious?
5. Should a clean day mean no bypasses, or simply staying under budget?

## Murkiness Questions

1. Does murkiness start exactly at budget exceeded, or only after bypass?
2. Should crossing the limit create mild murkiness even before bypass?
3. Should each bypass add a fixed 20%, or should long bypasses add more?
4. Should murkiness reset every day, or fade down gradually?

## Restriction Questions

1. Which apps should be blocked by default during onboarding examples?
2. Should websites be included in the same distraction bucket?
3. Should categories be discouraged because they are less predictable than specific apps?
4. Should "utility apps" be explicitly explained as exempt?

## Current Recommendation

Start with the simplest useful rule:

- User chooses distraction apps.
- User sets one daily budget for those apps.
- 80% creates warning.
- 100% applies shield.
- Bypass increases murkiness.
- Clean day means no bypass after budget.

This gives TimeTank a clean emotional promise and a technically stable Apple Screen Time implementation.
